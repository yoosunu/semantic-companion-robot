## 역할: "무엇을" 정하고, "어떻게"는 맡긴다
```
task_manager (내 코드)   무엇을, 어떤 순서로, 실패하면 어떻게       ← 판단
Nav2                     경로·장애물 회피·속도 (어떻게 가나)        ← 맡김
SLAM / AMCL              지금 어디 있나, 지도                       ← 맡김
ugv02_bridge (내 코드)   바퀴 ↔ ROS
```
- 실무에서도 같은 구조: 상위 작업 관리가 Nav2·SLAM 을 서비스처럼 불러 쓰고, 아래층은 설정만 맞춘다.
- 나중에 LLM 은 이 노드 **앞**에 붙는다: 자연어 → 정해진 명령 형식. 실행 여부는 task_manager 가 검증해서 결정 (LLM 출력은 신뢰하지 않음).

## 출발점: 지금 있는 도구에서 무엇이 부족한가
- `scripts/shuttle.py` `go()`: Nav2 액션(NavigateToPose)으로 목표 하나 보내고 **결과가 올 때까지 막혀서 기다림** → 그동안 아무 판단도 못 함
- `scripts/tour.py` 192~198행: 판단은 `if result == "REJECTED": break` 한 줄. ABORTED 는 그냥 다음 지점으로
  (10-23 순회: 12번 지점에서 273 s 갇혔다 ABORTED → 그대로 13번으로 넘어감)
- 필요: **이벤트 기반**(배터리 등이 들어올 때마다 반응) + **상태**(지금 무슨 일 중인가)를 기억하는 상태 기계

## 거절은 세 군데서 생긴다
| | 누가 | 언제 | 예 | 처리 |
|---|---|---|---|---|
| 검증 거절 | **task_manager** | Nav2 에 보내기 전 | 장소가 목록에 없음, 배터리 부족, 다른 일 중 | 이유와 함께 응답, IDLE |
| REJECTED | Nav2 | 접수 단계 | Nav2 가 아직 안 켜짐/꺼짐 (거의 이것뿐) | 잠깐 대기 후 재시도 N번 → 안 되면 알림 |
| ABORTED | Nav2 | 접수 후 실행 중 | 장애물에 막힘, 경로 없음, 진행 없음 | 1번 재시도 → 또 실패면 다음 장소 (없으면 IDLE + 알림) |
- 배터리는 Nav2 가 모른다 → 내 검증 단계에서 거른다
- 장애물로 갈 수 있는지는 보내기 전엔 확실히 모른다 → Nav2 에 맡기고 ABORTED 로 받는다

## 상태 기계 v0
```
[IDLE] ── 명령 ──► [검증: 장소 있나? 배터리 충분한가? 다른 일 중 아닌가?]
                        │ 거절 → 이유와 함께 응답 → IDLE
                        ▼
                  [NAVIGATING] ── SUCCEEDED ──► 남은 장소 있으면 다음, 없으면 IDLE
                        │── ABORTED ───► 1번 재시도 → 또 실패면 다음 장소 (없으면 IDLE + 알림)
                        │── REJECTED ──► 잠깐 대기 후 재시도 (최대 N번) → 안 되면 알림
                        └── 배터리 낮음 ─► 지금 목표 취소 ─► [RETURNING] (최우선, 다른 명령 무시)
                                                              └── 도착 ─► [CHARGING]
```

## 첫 질문들에 대한 내 답 (v0, 그대로)
1. 검증에서 거절할 경우: 장소가 없음 / (장애물 등으로 못 감 → Nav2 의 ABORTED 로 받기로 정리) / 배터리 부족
2. 성공 후: 정답 없음. 다음 장소가 있으면 계속, 없으면 IDLE
3. ABORTED: 재시도는 한 번이면 충분. 그래도 안 되면 다음 경로(장소)로
4. REJECTED: 재시도 의미 있음 (상태가 바뀔 수 있으니). 안 되면 나에게 알리거나 집으로
5. 배터리 낮음: 먼저 귀환해서 충전할 수 있는지 판단. "귀환 중" 상태는 필수, 최우선

## 열린 질문 (실험 거리)
- 배터리 기준을 고정값(예: 20%)이 아니라 **집까지 거리에 따라** 정해야 하지 않나? 멀리 있으면 더 일찍 귀환
- 귀환 중 Nav2 가 ABORTED 를 내면? (최우선 작업이 실패하는 경우)
- 명령은 어떤 형식으로 받나 (토픽 / 서비스 / 액션)? LLM 이 같은 형식으로 보낼 수 있어야 함

## 구현 계획
- 장소 목록: `places.yaml` (이름 → 지도 좌표). 나중엔 시맨틱 맵이 자동으로 채움
- 첫 구현: IDLE → 검증 → NAVIGATING → SUCCEEDED 한 줄만. 이어서 ABORTED 재시도, 배터리 귀환
- 첫 미션: L4 "갔다가 돌아오기" → 순찰 → 실패를 일부러 만들어(벽 안 좌표 등) 처리 확인
- 역할: 액션 통신 등 상투적인 뼈대는 Claude, **상태 전이·검증·실패 처리는 Jasper**
- 언어: 미정 (Python: 빠른 수정·LLM 연결 / C++: 채용 공고·브리지 연속성)
