# Roadmap — Semantic Companion Robot

> 길을 잃으면 이 파일을 본다. 원칙: 아래 계층이 **수치로 합격**해야 위 계층을 올린다 (CLAUDE.md "통합 원칙").
> 마지막 갱신: 2026-10-14 (목표 기준서 반영)

## 왜 하는가 (프로젝트의 목적)
- **강한 신입 포지션**: 채용 공고 요구 역량(C++, Linux, ROS 2, 하드웨어 통합)과 가장 겹치는 프로젝트로 선정.
- "해봤습니다"가 아니라 **"왜 이걸 썼고, 전과 비교해 무엇이 얼마나 나아졌는가"를 수치로 말한다.**
  → 모든 결정은 이유를, 모든 개선은 before/after 숫자를 남긴다 (아래 "증거 장부").
- 차별점: 가져다 쓴 것(SLAM, Nav2)과 **직접 만든 것(브리지, 판단, 시맨틱, 충전)을 분명히 구분**해서 말할 수 있다.

## 미션
SLAM으로 맵을 그리고, Nav2로 이동하면서, 비전과 직접 짠 알고리즘으로 어디로 갈지 스스로 판단한다.
단순히 돌아다니는 게 아니라 **사람과 물건을 알아보고, 배터리를 스스로 관리(무선 충전)하며, 사람 손 없이 방에서 상시 운용**된다.
LLM은 자연어 → 정해진 명령 형식 번역만 하고, 실행 여부는 직접 작성한 `task_manager`가 검증해 결정한다
("end-to-end는 믿을 수 없으니 task_manager가 통제한다").

## 학습 방식: 미션 사다리 (2026-10-19 결정)
작고 구체적인 **행동 미션**을 세우고 오른다. 미션이 요구하는 부품(브리지, odom, 지도, LiDAR...)은 막힐 때 파고든다.
- 미션마다 **숫자 기준 하나** (도착 오차, 최소 거리 등). "됐다"의 기준이 없으면 바이브가 된다.
- 미션이 끝나면 **세 줄 기록**: 어떤 부품을 거쳤나 / 어디서 막혔고 왜였나 / 숫자.
- 배우는 순서는 위에서 아래로(결과 먼저), **붙이는 순서는 새 미지수 하나씩**(원인을 찾을 수 있게).
- 같은 사다리를 시뮬(TB3 월드 기둥 9개)과 실물(방, 의자=기둥)에서 오르고 숫자를 비교한다.

## 1단계 세부 (현재) — "TB3를 UGV02라고 가정하고 내 브리지로 움직이기"

```
teleop / Nav2 ── /cmd_vel ──→ ugv02_bridge (Jasper) ──JSON over 가상 시리얼──→ fake_esp32 ──→ Gazebo TB3 가 움직임
                 /odom   ←──      (번역기)          ←──JSON 피드백(바퀴·IMU·전압)──     ←── Gazebo
```
- fake_esp32: UGV02 펌웨어인 척하는 프로그램. JSON을 받아 Gazebo 로봇을 움직이고, Gazebo 상태를 UGV02 형식 JSON으로 돌려준다.
