# 004 — 브리지가 죽었는데 로봇이 계속 움직임 (2026-10-31 발생, 11-03 원인·해결)

## 증상
10-31 거실 탐색 1차: 문턱에서 차체가 고꾸라진 뒤 명령을 넣어도 로봇이 안 멈춤 → Pi 재부팅으로 정지.

## 증거 (`scripts/run_report.py` 로 Pi `~/.ros/log` 분석)
- 브리지 로그가 종료 메시지(`sent stop (shutdown)`) 없이 끊김. 마지막 명령 `T:13 X=-0.049 Z=-0.283` (0 아님)
- 2초 뒤부터 explore: `Extrapolation Error … latest data is at time 1793458104.8` 반복 → odom 이 멈춤 = 브리지 사망/행
- 브리지 안의 안전장치(데드맨 0.5 s, 종료 시 정지)는 브리지가 살아 있어야 돈다 → 크래시·행에는 무력

## 시험 (11-03, 바퀴 띄움, 명령 1번 → 6초 침묵, 피드백 L/R 기록)
| # | 설정 | 명령 | 결과 |
|---|---|---|---|
| 1 | 없음 | T:13 X=0.1 | 6초 내내 돎 → 펌웨어 자동 정지 **없음** (문서상 기본 3 s 인데도) |
| 2 | T:136 cmd=500 | T:13 X=0.1 | 6초 내내 돎 → heartbeat 설정이 **안 먹음** |
| 3 | T:136 cmd=500 | T:1 L=R=0.1 | **0.5~0.8 s 에 정지** ✅ |

## 원인
Waveshare 펌웨어 소스(ugv_base_ros `uart_ctrl.h`): heartbeat 타이머(`lastCmdRecvTime`)를 T:1·T:11 만 갱신하고
T:13(`rosCtrl`)은 갱신 안 함 (ugv_base_general 최신판은 갱신함 → 버전 차이). 우리는 T:13 만 써서 heartbeat 가 한 번도 적용 안 됨.
의심의 출발: Jasper — "문서에 있는 기능이 아예 안 먹는 게 이상하다".

## 해결 (bridge v4)
- 주행 명령을 T:13 → **T:1** 로: `L = x − z·track/2`, `R = x + z·track/2` (펌웨어 rosCtrl 과 같은 식, track 0.170 실측)
- 시작 시 `{"T":136,"cmd":500}` 전송 (ESP32 재부팅 시 기본값으로 돌아가므로 매번)
- 효과: 브리지 크래시·행, Pi 전원 차단 모두 0.5 s 내 펌웨어가 스스로 정지
